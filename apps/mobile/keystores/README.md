# Android signing keys

This directory holds the **release** signing key. Only this README is committed;
the keystore and its passwords are gitignored (`*.keystore`, `credentials.json`).

| File                            | Committed | What it is                                        |
| ------------------------------- | --------- | ------------------------------------------------- |
| `sente-release.keystore`        | no        | PKCS12, RSA 4096, alias `sente-release`, 10k days |
| `credentials.json`              | no        | EAS-format credentials: path, alias, passwords    |
| `../android/app/debug.keystore` | no        | Regenerated by `expo prebuild` from the template  |

`credentials.json` is `chmod 600` and is exactly the shape `eas build --local`
and `eas credentials` expect, so `eas.json` can point at it with
`"credentialsSource": "local"`.

## Why a release key exists before there is anything to release

`assetlinks.json` must list **both** fingerprints, and it is served from a host
we deploy separately. Debug-only association works for the entire development
cycle and fails the first time anyone installs a release APK — which is demo
day. Generating the key costs nothing (the $25 Play fee is for _publishing_;
judges install the APK directly), so it is generated now and both fingerprints
are already in `infra/site/.well-known/assetlinks.json`.

release  15:FA:4B:41:D1:C8:44:C2:F7:9F:B7:B8:3A:5D:B6:6D:39:B8:1E:8C:D3:46:90:F8:C3:A1:6B:55:9F:AF:36:55

```bash
# debug — the stock Android debug key that ships in the Expo template, so this
# value is stable across `expo prebuild --clean` and across machines.
keytool -list -v -keystore android/app/debug.keystore \
  -alias androiddebugkey -storepass android

# release — password is in credentials.json
keytool -list -v -keystore keystores/sente-release.keystore \
  -alias sente-release
```

## Losing the release key

There is no recovery and no re-issue. A different key means a different
fingerprint, which means `assetlinks.json` no longer matches, which means every
passkey scoped to `sente.lol` stops being offered to the app — and because the
wallet is derived from the passkey, that is the whole account, not just the
login. Back this directory up somewhere off this machine.
