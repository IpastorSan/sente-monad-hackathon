# Sente — trading capability research (for a trading-first mobile UI)

Read-only research, 2026-09-27. Repo: `~/Work/moveseventyeight/sente`. All paths are relative to it.
Line numbers are from the working tree of that date. "Status" vocabulary:

- **exists**: implemented in our code and reachable (at least server-side).
- **adapter-only**: in `@sente/venues`, but no API route or agent tool exposes it.
- **SDK/venue-only**: the venue or its SDK can do it; our code never calls it.
- **needs building**: neither.

Headline: **every trading capability today lives inside `@sente/venues` adapters and is
reachable only by agents through `services/api/src/agents/tools/registry.ts`.** The API's
`/venues` module is a stub (`services/api/src/venues/venues.controller.ts:5-17`,
`venues.service.ts:27-32` return `implemented: false`, empty registry). There is no market-data
route, no quote route, no candles route, and no user-order route.

---

> **Superseded since this was written (2026-10-09).** Agents now run on a per-agent schedule
> (`PATCH /agents/:id/schedule`, one minute to seven days, SEN-67/SEN-71) polled every
> `AGENT_SCHEDULER_POLL_SECONDS` (default 15 s), with a credits guard and a daily run cap;
> `AGENT_TICK_SECONDS` is only the default cadence for agents without their own. Watchers
> (SEN-182) wake a scheduled agent when a price or indicator condition fires, checked without the
> model (`docs/agents.md`, "Watchers"). Agents also have `get_klines`, `quote` and
> `get_indicators` (SEN-79, SEN-180), and users trade both venues themselves (`/trade`,
> `docs/user-trading.md`). Rows below that say otherwise describe 2026-09-27.

## 5. Who places orders; can a USER trade manually?

**Today only agents trade.** An agent's orders are signed by its own Privy server wallet (EOA) with
the enclave-enforced mandate policy, after our gate (`tools/gate.ts`, `record_thesis` required
before any order) — `docs/agents.md:6-18`. The agent is the AccountCore root on Kuru and owns its
Perpl account and API key. Kuru transactions are signed by Privy and broadcast by us, one at a time,
**not atomically** (approve and deposit are separate transactions) (`docs/agents.md:50-77`). Perpl
orders are gasless: they are forwarded over the trading WS once `allowOrderForwarding(true)` is set
(`perpl/trading.ts:1-18`).

**The ownership gotcha, restated for the design:** the _user's_ venue accounts would be different
accounts from the _agents'_ accounts, and the Kuru owner and Perpl owner can differ (CLAUDE.md #9:
Kuru root = contract account OK; Perpl owner must be an `ecrecover`-able EOA). Gotcha 9 was written
for the Kernel + passkey EOA model; the user account has since moved to the Privy wallet (SEN-40),
and a Privy wallet can plausibly own both, but that is unproven for Perpl enrollment. Funds a user
hands to an agent sit in the **agent's** wallet and venue accounts, so a user cannot trade them
manually. The only user actions on agent funds are revoke, amend and `POST /agents/:id/return`.

Kuru faucet: 10,000 USDC + 1 WETH + 0.1 cbBTC + 1 XAUt per address every 12 h (`kuru/constants.ts:140-157`).
Perpl: 100 AUSD minimum to open an account on testnet (`docs/monad-testnet-assets.md:160-170`).

**"Preset bot with configurable strategy" maps onto:** a _template_ = `{systemPrompt, strategy
text rendered from parameters, model, suggested mandate preset}`. Hiring from a template is just
`POST /agents` with rendered text (no backend change needed for a v1: render on the phone), or a
fork of a curated public "house" agent (SEN-28 already supports it). The strategy is **advisory
text interpreted by an LLM**, not deterministic code, so a parameter is guidance, not a guarantee.
The only hard guarantees are mandate fields.

Natural parameters to expose:

- **Hard (enforced; map to mandate):** venues, markets, max order size (`maxOrderNotional`), max
  leverage, deposit/collateral caps, rolling spend cap, duration (`expiresAt`).
- **Soft (strategy text):** style (trend/mean-reversion/market-making/news), direction bias
  (long-only/short-ok), target position size % of capital, take-profit % / stop-loss % (the agent
  acts on them only when it runs), max concurrent positions, order-type preference (post-only
  maker vs taker), and "do nothing unless…" thresholds.
- **Operational (needs building):** run cadence per agent (today it is global), model choice
  (2 options exist).

## Design constraints (what the UI must respect or not promise)

- **No stop-loss / take-profit orders, on either venue.** Kuru's triggers are disabled on the
  testnet Relay; Perpl's are unimplemented and unverified. An "SL/TP" field can only be a _soft_
  instruction the agent checks when it runs (on 2026-09-27 runs happened only on manual trigger
  or a global ≥30 s timer that was off by default; since then, per-agent schedules and watchers,
  see the note at the top). Label it that way, or leave it out.
- **"Market" orders are bounded IOC limits.** Every market order needs a worst price. Show max
  slippage (the default can be computed) and expect partial fills with the rest cancelled.
- **Kuru: no reduce-only, no GTD/expiry, no amend, no leverage.** Perpl: isolated margin only,
  leverage is per order (no "set account leverage"), no add-margin, no amend.
- **Two quote currencies:** Kuru markets are in **Kuru Testnet USDC**; Perpl in **AUSD**. They are
  different tokens, and a combined P&L sums them as if both were dollars. Don't show "USDC" for Perpl.
- **Kuru market list is 4 hard-coded pairs** (MON, WETH, cbBTC, XAUt / USDC). Perpl's is dynamic
  (7 on testnet). A "search all tokens" UI has nothing behind it.
- **Minimums:** Kuru enforces a min _notional_, not a min size; Perpl's real floors are not surfaced
  yet. A Perpl account needs **100 AUSD minimum** to open on testnet.
- **Charts come from venue candles.** Kuru max 5000 candles per request, Perpl 1024; no Perpl 1w;
  volumes are quote-denominated (base volume is an estimate). No live candle streaming yet.
- **No real-time channel to the app.** Design for polling (1–5 s) with "as of" timestamps. Don't
  promise a tick-by-tick book.
- **Only agents trade today.** A manual "Buy/Sell" button for the user needs new signing flows
  (phone-verified arbitrary calls from the Privy wallet), venue onboarding (Kuru deposit; Perpl
  3 txs + 100 AUSD + API key), and non-atomic multi-step UX with a status for each step.
- **Funds given to an agent are the agent's.** The user cannot manually trade or close an agent's
  position directly. They can revoke, amend (device-signed), run the agent with an instruction, or
  `return` funds.
- **Agents are LLM-driven:** strategies are free text with no backtest and no determinism. Only
  mandate caps are guarantees (and `maxOrderNotional` / `maxLeverage` are enforced by our gate, not
  the enclave). Agents currently **cannot see price history** (no klines tool).
- **Agent P&L:** realised P&L from `verdict` events is fine to show. Unrealised P&L exists only for
  Perpl positions, and only through a tool. Leaderboard numbers need the indexer, which is not
  deployed (the `unconfigured` state must render). The event log is in memory, so it is lost on
  restart.
- **Perpl liquidation price is our computation** and excludes accrued funding; label it "est."
- Everything is **Monad testnet (10143)** only. There are no mainnet addresses for Kuru V2.

## Smallest backend additions that unlock the trading UI

1. **Market-data routes on the stub `VenuesModule`** (S–M): register a read-only `KuruVenue`
   (publicClient only) and a public-read Perpl client (split `PerplVenue` so reads need no
   credentials). Expose `GET /markets` (merged, with fees/min notional/max leverage),
   `GET /markets/:venue/:symbol/ticker` (Kuru bestBidAsk/BBO; Perpl `state.mrk/lst/bid/ask`),
   `/depth`, `/klines`, `/quote?side&size`. Add a server-side cache: one held Perpl market-data
   subscription instead of a socket per request, because of the 10 req/min limit.
2. **Agent portfolio route** (S): `GET /agents/:id/portfolio` → balances (venue + wallet), open
   orders, Perpl positions (entry/mark/liq/uPnL), reusing `AgentVenues.forAgent` and the read tools.
3. **`get_klines` + `quote` agent tools** (S): the adapters already implement both, and strategy
   templates such as trend or breakout need them.
4. **Per-agent run cadence** (S–M): a `schedule` field on the agent, replacing the global
   `AGENT_TICK_SECONDS`. Pair it with a credits guard.
5. **Strategy templates** (S): a static catalog of `{id, name, description, params schema,
render(params) → strategy/systemPrompt, suggested mandate preset}`. Rendering can happen on the
   phone; the hire route is unchanged. Optionally, "house" public agents to fork.
6. **Durable event log** (S–M): the in-memory log backs P&L cards and loses history on restart.
7. **Later / larger:** SSE stream of agent events and prices (M); user manual trading from the
   Privy wallet with phone-side call verification (Kuru M, Perpl M–L); deploy the indexer (M; Perpl
   cannot be indexed on Envio's plans since SEN-171, `docs/indexer.md` §budget); SL/TP (L, research-gated on Perpl triggers).
